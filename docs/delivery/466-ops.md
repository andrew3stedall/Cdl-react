# #466 Operations and verification lane

This execution record covers #475, #476, and the operations slice of #531 on
`milestone/466-ops`. It is source and CI evidence only; it records no cloud
mutation or live recovery proof.

## Changes

- Runtime images install frontend packages with `npm ci` from
  `frontend/package-lock.json` and Python packages with `uv sync --frozen`
  from `uv.lock`. CI uses `npm ci` and `uv sync --locked`.
- A runtime Cloud Run revision is staged while the last healthy revision keeps
  100% traffic. The migration job image must match the immutable application
  image. Alembic upgrades to the checked-in head and then reads PostgreSQL's
  recorded heads back; a mismatch or migration error blocks promotion.
- Auto rollout, reviewed Terraform runtime apply, and direct fallback share the
  revision pin, migration, no-traffic readiness/auth-boundary smoke, then
  traffic-promotion sequence. The direct fallback keeps a failed migration
  from reaching the image-update step.
- The PostgreSQL release journey authenticates two managers through real DB
  sessions, creates and accepts a targeted invite, round-trips a lineup and
  chip state, and checks manager isolation. The Playwright smoke uses current
  20-player / five-chip browser fixtures at mobile and desktop widths and
  asserts interaction and overflow invariants. It collects no screenshots.

Current checked-in Alembic head: `0029_targeted_league_invites`. This is the
source revision only; no live staging schema revision was read from Cloud SQL.
